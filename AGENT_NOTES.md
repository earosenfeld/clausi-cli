# Agent Notes (clausi-cli)

Reusable, non-obvious discoveries for future workers. Keep entries short.

- 2026-08-20: The dev venv at `clausi-cli/venv/` is a **Windows** venv (`venv/Scripts/python.exe`, not `venv/bin/`). From WSL bash, invoke it directly as `./venv/Scripts/python.exe` — activation scripts don't work under WSL bash. It was missing `pytest`/`anthropic`/`pathspec` (only click/openai/pyyaml/rich were installed) — `pip install` them in first if tests fail with `ModuleNotFoundError`.
- 2026-08-20: When testing the Windows venv python from WSL, pass paths relative to the repo (not `/tmp/...` — that's WSL-only and invisible to the Windows process) and set env vars via `os.environ[...]` inside the script rather than shell `export`, since exported WSL env vars don't reliably cross into a directly-invoked `.exe` child.
- 2026-08-20: `Path.home()` inside that Windows venv resolves to Eric's real `C:\Users\Eric` — ad hoc smoke tests that exercise `clausi scan` for real will write to his actual `~/.clausi/cache` and (on first run) `~/.clausi/config.yml`. Clean up (`rm` the cache entries you created) after manual smoke testing; don't leave test artifacts in his real config dir.
- 2026-08-20: `.gitignore` had `clausi/core/docs_generator.py` (+ a nonexistent `docs_prompts.py`) excluded as "proprietary prompts (backend only)" — the file was never in git history at all, only shipped via PyPI sdist built locally. Now that docs_generator.py is a local BYOK reimplementation with no proprietary backend prompts, that ignore rule was removed so the file is actually in the repo — check `git log -- <path>` before assuming a tracked-looking source file is really tracked; `.gitignore` can silently exclude files that still exist on disk and get built into the package.
- 2026-08-20: `core/clause_selector.py` `CLAUSE_PRESETS` had been broken since it was written — its clause IDs (`EUAIA-3.1`, `GDPR-5.1`, etc) never matched the real `id:` fields in `data/regulations/*.yml` (`Article-9`, `Clause-4`, `Security-Rule-164.308`, ...). Matching is exact-string (`compliance_analyzer.py`), so every `--preset` scan across all 5 regulations silently matched zero clauses. Fixed by remapping to real IDs — verified via a script that intersects preset IDs against actual clause IDs (see git history around this date). If you touch presets or regulation YAML clause IDs, re-run that kind of check — there's no test that would have caught the original mismatch other than one hardcoded assertion.
